<section class="section soft" id="considerations">
  <div class="container">
    <div class="sec-label">04 / CONSIDERATIONS</div>
    <h2>昱展新藥選型時，真正需要回答的 6 個問題</h2>
    <p class="sub">建議不要先從產品名稱選，而是先決定昱展希望「解決一次送件的效率」還是「重建長期法規資訊管理模式」。</p>
    <div class="fit">
      <div class="card">
        <div class="kicker">WHEN GLOBALSUBMIT FITS BETTER</div>
        <h3>若目前最大痛點是 Publishing / QC / Review</h3>
        <p>當來源文件管理已有既定系統或流程，主要希望縮短 eCTD 製作時間、強化 validation、快速 QC hyperlinks/bookmarks，以及提升跨 Submission review 效率時，GlobalSubmit 的價值會更直接。</p>
      </div>
      <div class="card">
        <div class="kicker">WHEN eCTD247 FITS BETTER</div>
        <h3>若希望將 EDMS 與 Submission Lifecycle 一起納管</h3>
        <p>當痛點包含來源文件版本、權限、審閱、歷次 sequence、不同市場送件內容與追溯性，並希望降低 ZIP / NAS / 檔案夾分散管理時，eCTD247 的整合式架構較吻合。</p>
      </div>
    </div>

    <div class="decision">
      <div class="card"><div class="num">Q1</div><h3>來源文件放哪裡？</h3><p class="mini">目前是否已有成熟 DMS / SharePoint？未來是否希望與 eCTD 同一平台？</p></div>
      <div class="card"><div class="num">Q2</div><h3>誰負責 Publishing？</h3><p class="mini">內部 RA 自製、外包廠商，或混合模式？是否要把 know-how 收回內部？</p></div>
      <div class="card"><div class="num">Q3</div><h3>一年有多少 Sequence？</h3><p class="mini">產品數、市場數與變更頻率，會直接影響 lifecycle 管理的價值。</p></div>
      <div class="card"><div class="num">Q4</div><h3>Review 如何進行？</h3><p class="mini">目前是否需要反覆下載、比對 PDF、Email 確認與人工追蹤？</p></div>
      <div class="card"><div class="num">Q5</div><h3>是否要回溯歷史 Submission？</h3><p class="mini">需不需要快速回答「這個內容哪次送過、哪個市場版本不同、來源文件是什麼」？</p></div>
      <div class="card"><div class="num">Q6</div><h3>IT / Validation 模式？</h3><p class="mini">偏好 SaaS 快速啟用，或需自有 IT 架構、驗證文件與內部維運？</p></div>
    </div>

    <div class="callout">
